## Overview

answerLoops receives posts and comments from the Circle spaces you select and turns each one into a ticket. It drafts an answer from your workspace knowledge, and a separate AI reviews that draft. Your team reads the reviewed draft on the ticket and posts the answer in Circle by hand. answerLoops never posts anything to Circle.

Posts and comments reach answerLoops through Circle Workflows that your community administrator sets up.

### What you need in Circle

- **A Scale or Circle Plus plan.** Circle has no built-in webhook subscriptions. answerLoops receives posts through a Workflow that uses the **Send to webhook** action, and Circle offers that action only on its Scale and Circle Plus plans. The Business plan includes Workflows and the Admin API, but not **Send to webhook**.
- **A community admin** to create the Admin API token and the two Workflows.

## Setup

### 1. Create an Admin API token

In Circle, go to **Settings → Developers → Tokens**, create a new token, and choose type **Admin V2**. Copy it.

answerLoops uses this token only when a webhook arrives without the text of the post or comment. It then looks up that one record. Each lookup counts toward your community's monthly Admin API quota in Circle.

The token stops working if the admin who created it loses admin rights in the community. If that happens, create a new token as a current admin and save it on the Circle card.

### 2. Connect in answerLoops

Go to **Integrations → Circle** and fill in:

| Field | Value |
| --- | --- |
| Community URL | Your Circle community's base URL, e.g. `https://community.example.com` |
| Admin API token | The token from step 1. Required. |
| Watched space IDs | Numeric space IDs, comma-separated. Leave blank to watch every space. Only posts in these spaces open tickets. A comment on a post that already has a ticket is always added to it. |

Click **Connect**. The card then shows two Endpoint URLs, one for posts and one for comments, with your secret already in them.

### 3. Create the two Circle Workflows

In Circle, open **Workflows** in the left sidebar and create a Workflow for posts:

- **Trigger:** **Published a post**
- **Action:** **Send to webhook**
- **Endpoint URL:** the posts URL from the Circle card. It looks like this:

```text
https://<your-answerloops-domain>/api/circle/webhook?kind=post&token=<your-secret>
```

Then create a second Workflow for comments:

- **Trigger:** **Posted a comment**
- **Action:** **Send to webhook**
- **Endpoint URL:** the comments URL from the Circle card:

```text
https://<your-answerloops-domain>/api/circle/webhook?kind=comment&token=<your-secret>
```

The **Send to webhook** action takes only an endpoint URL, so the secret goes in the URL as `token`. Keep both URLs private. The `kind` value tells answerLoops whether the event is a post or a comment, so keep `kind=post` on the first Workflow and `kind=comment` on the second. If you send events from another tool that can set request headers, answerLoops also accepts the secret in an `X-AnswerLoops-Token` header.

Turn both Workflows on.

### 4. Check delivery

In each Workflow, click **Test webhook** to send a sample event to answerLoops. Once members start posting, open **Workflows → History** in Circle to see each run and whether it succeeded.

### 5. Set the confidence threshold

**Confidence threshold** (0–1, default `0.8`) is the score below which the draft is flagged as low-confidence on the ticket.

## Answering in Circle

Open the ticket in answerLoops, read the draft, and edit it if needed. Click **Copy draft** and paste it as a comment on the member's Circle post. Then click **Approve** on the ticket to record the answer there. Approving doesn't post anything to Circle.

## Good to know

- **Edits and deletions in Circle don't change the ticket.** Circle Workflows have no trigger for edited or deleted posts, so the ticket keeps the text as it was first published.
- **Reconnecting creates a new secret.** If you disconnect Circle and connect it again, the card shows a new secret token. Update the `token` value in the Endpoint URL of both Workflows, or Circle's events stop reaching answerLoops.

## Rotating the secret

The secret is created when you first connect and stays the same when you edit the card's settings. To replace it, click **Rotate secret** on the Circle card and confirm. Only owners and admins can rotate it.

The old secret stops working as soon as you confirm. The card then shows both Endpoint URLs with the new secret in them. Paste each one into its Circle Workflow, the one for new posts and the one for new comments. Until both are updated, Circle's webhooks won't create tickets.

## Disconnecting

Click **Edit spaces**, then **Disconnect**, and confirm. New posts and comments stop creating tickets right away. If you connect again later, answerLoops generates a new secret, so both Workflow URLs will need updating.

---

## Environment variables reference

Circle is configured entirely per-organization in the Settings UI. There is no community-wide credential and no environment variable to set. The API token is stored encrypted at rest — set `ENCRYPTION_KEY` before connecting in any real deployment.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Posts aren't creating tickets">
    Open **Workflows** in Circle and check that both Workflows are turned on. Then open **Workflows → History** and look at the most recent runs. Make sure each Workflow's Endpoint URL matches the one on the Circle card, includes the right `kind=post` or `kind=comment`, and has `token=` set to the secret shown on the card. Click **Test webhook** in the Workflow to send a sample event. If you set **Watched space IDs**, posts in any other space are ignored on purpose, so clear the field to watch everything. Posts shorter than 10 characters are skipped.

    Every delivery answerLoops accepts but doesn't turn into a ticket is logged as `Circle webhook delivery acknowledged without ingesting`, with the post or comment id and a reason: `no record`, `no id`, `too short`, `no author`, or `outside watched spaces`. The log never includes the post's text. On a self-hosted install, search the app logs for that line to see why a post was skipped.
  </Accordion>
  <Accordion title="The ticket's link opens the wrong page">
    A ticket links to the post's `url` from the webhook payload only when it is an `https://` address on your **Community URL**'s host. Otherwise the link is built as `<Community URL>/posts/<post id>`. If links point at the wrong place, check that the **Community URL** on the Circle card matches the address members use, including any custom domain.
  </Accordion>
  <Accordion title="Events stopped arriving after I reconnected Circle">
    Disconnecting and connecting again creates a new secret. Copy the new secret from the Circle card and update the `token` value in the Endpoint URL of both Workflows.
  </Accordion>
  <Accordion title="Tickets are created but the content is empty or truncated">
    Circle Workflow webhooks vary in how much of the post they include. When the text is missing, answerLoops fetches the full post with the Admin API. Make sure the **Admin API token** you saved is a valid **Admin V2** token, hasn't been revoked, and belongs to someone who is still an admin of the community.
  </Accordion>
  <Accordion title="A Workflow run shows Failed with &quot;Could not fetch the full record from Circle&quot;">
    The webhook arrived without the post's text, and answerLoops couldn't fetch it from Circle's Admin API, so no ticket was created. The run is marked failed so you can see it in the Workflow's history rather than lose it quietly. Check that the **Admin API token** on the Circle card is a valid **Admin V2** token, hasn't been revoked, and belongs to someone who is still an admin of the community. If Circle's API was briefly unavailable, the next post goes through as normal.
  </Accordion>
  <Accordion title="I edited a post in Circle and the ticket didn't change">
    Circle Workflows have no trigger for edited or deleted posts, so the ticket keeps the text as it was first published. If a member rewrites their question, answer the new version in Circle directly.
  </Accordion>
  <Accordion title="A draft appears but nothing is posted in Circle">
    That's expected. answerLoops drafts and reviews the answer, then leaves it on the ticket for your team. Click **Copy draft**, paste it as a comment on the Circle post, then click **Approve** on the ticket to record it. If you'd rather write your own answer, type it in the reply box and click **Save reply**. If the draft is flagged as low-confidence, check it more closely before you post it.
  </Accordion>
</AccordionGroup>
