Find your symptom below, open it, and follow the fix. Problems are grouped by where you notice them. For most of them, the first thing to check is the logs.

```bash
docker compose logs app --tail=50
docker compose logs bot --tail=50
```

If you run the published-image or from-source stack, add `-f docker-compose.ghcr.yml` or `-f docker-compose.prod.yml` after `docker compose`.

## Quick lookup

| What you see | Most likely cause | Jump to |
|---|---|---|
| App will not start | Missing setting, or the database is not ready | [Startup and database](#startup-and-database) |
| `ECONNREFUSED` on port 5432 | Wrong database host, or Postgres still starting | [Startup and database](#startup-and-database) |
| `redirect_uri_mismatch` | Google redirect URI does not match `AUTH_URL` | [Sign-in and access](#sign-in-and-access) |
| No sign-in button | Google credentials not set | [Sign-in and access](#sign-in-and-access) |
| No AI draft on a ticket | No usable AI key | [Answers and AI](#answers-and-ai) |

| Data gone after a restart | Volumes were deleted | [Startup and database](#startup-and-database) |

## Startup and database

<Accordions>
  <Accordion title="The app will not start">
    Check the app logs first. Then look for these causes:

    - **A required setting is missing.** Add it to `.env` and restart. See the [minimum to boot](/docs/self-hosting/environment-variables#minimum-to-boot).
    - **The database is not ready.** Postgres can take a few seconds to initialise on first boot. Wait about 10 seconds, then run `docker compose restart app`.
    - **Port 3000 is already in use.** Change the host port in the compose file, for example `"3001:3000"`.
    - **Old setting names.** answerLoops uses `AUTH_SECRET` and `AUTH_URL`. Rename `NEXTAUTH_` variables if you are coming from an older deployment.
    - **A migration failed.** The log names the file that failed. Restore your backup if you are mid-upgrade, and see [Upgrading](/docs/self-hosting/upgrading).
  </Accordion>
  <Accordion title="Database connection refused (ECONNREFUSED)">
    The app cannot reach Postgres. Either it is still starting or `DATABASE_URL` points at the wrong host.

    1. Restart the app: `docker compose restart app`.
    2. If it persists, check that Postgres is running: `docker compose ps` and `docker compose logs postgres --tail=20`.
    3. Make sure `DATABASE_URL` uses the service name as the host (`postgres`), not `localhost`, when the app runs in the default compose stack:

    ```
    DATABASE_URL=postgresql://community:<your-password>@postgres:5432/community
    ```

    The default compose file sets this for you. Bring-your-own-Postgres stacks use the address you provide.
  </Accordion>
  <Accordion title="Live updates or settings changes do not appear">
    If `DATABASE_URL` goes through a connection pooler, live updates and config reload need a direct connection. Set `DIRECT_DATABASE_URL` to your provider's direct or session-mode connection string and restart.
  </Accordion>
  <Accordion title="All my data disappeared after a restart">
    The database volume was deleted, most likely by `docker compose down -v`. The `-v` flag removes named volumes, including `postgres-data`. This cannot be undone without a backup.

    Stop the stack with `docker compose down` and never add `-v` unless you mean to wipe everything. See [Upgrading](/docs/self-hosting/upgrading) for how to take backups.
  </Accordion>
  <Accordion title="The onboarding wizard appears on every login">
    The workspace has not finished onboarding. Complete the wizard once: name your workspace and click through the steps (you can skip optional ones). To check the state directly:

    ```bash
    docker compose exec postgres psql -U community -d community \
      -c "SELECT id, name, onboarded_at FROM orgs;"
    ```

    An empty `onboarded_at` means onboarding has not finished.
  </Accordion>
</Accordions>

## Sign-in and access

<Accordions>
  <Accordion title="Google shows redirect_uri_mismatch">
    The redirect URI registered in Google does not match what your instance sends. Sign-in is Google only, so there is a single address to fix:

    ```
    https://<your-domain>/api/auth/callback/google
    ```

    Add it exactly as shown under your OAuth client's authorized redirect URIs. Then make sure `AUTH_URL` in `.env` matches your public address, including `https://`, with no trailing slash. See [OAuth setup](/docs/self-hosting/oauth).
  </Accordion>
  <Accordion title="The sign-in page has no button">
    The page only offers a method whose credentials are set. Set `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` in `.env` and restart.
  </Accordion>
</Accordions>

## Answers and AI

<Accordions>
  <Accordion title="An AI draft never appears">
    Open the ticket. Where the draft would be, a notice explains why there is none (see [When a ticket has no draft](/docs/product/tickets#when-a-ticket-has-no-draft)). Bug reports and feature requests are never answered automatically, and email from an unverified sender is held for a person, so no draft is expected for those.

    For an ordinary question on a self-hosted instance, a missing draft usually means there is no usable AI key. Go to **Settings → AI Model** and add one, or set `OPENAI_API_KEY` in `.env` and restart. The Settings page shows a **Key saved** badge after a successful save.

    Anthropic, Gemini, Groq, and Mistral keys can only be saved in **Settings → AI Model**; they are not read from `.env`.
  </Accordion>
  <Accordion title="Knowledge-base search or import fails after switching chat provider">
    A chat provider other than OpenAI cannot produce embeddings. Add an OpenAI key in the **Embeddings** section of **Settings → AI Model**. See [AI model settings](/docs/product/ai-config#self-hosted-installs).
  </Accordion>
  <Accordion title="Emails are not sending">
    1. Check that `RESEND_API_KEY` is valid.
    2. Check that `RESEND_FROM` is an address on a domain verified in your Resend dashboard.
    3. Look at the logs: `docker compose logs app --tail=50 | grep -i resend`.

    Without these settings, email notifications are skipped silently.
  </Accordion>
</Accordions>

## Channels

<Accordions>
  <Accordion title="The bot is connected but never replies in the channel">
    **Automatic Deflections** is off by default. While it is off, answers are held as drafts on the dashboard for your team to approve, edit, or dismiss, and nothing is posted to the channel on its own. Turn it on for the channel in its integration settings once you trust the answers.
  </Accordion>
  <Accordion title="Knowledge-base syncs or re-indexing never finish">
    The **bot** service runs those jobs. Check that it is running (`docker compose ps`) and that `BOT_SECRET` is set to the same value on the app and the bot. If the bot and app are on different hosts, set `BOT_TARGET_URL` on the bot to the app's address.
  </Accordion>
  <Accordion title="The bot gets 404 on /api/ingest">
    The bot adds `/api/ingest` to the end of `BOT_TARGET_URL`, so a trailing slash or period breaks the address.

    | Value | Result |
    |---|---|
    | `https://app.example.com` | Works: `https://app.example.com/api/ingest` |
    | `https://app.example.com/` | Broken: `https://app.example.com//api/ingest` |
    | `https://app.example.com.` | Broken: `https://app.example.com./api/ingest` |

    Use the bare address with nothing after it.
  </Accordion>
  <Accordion title="The Discord channel picker says loading forever">
    The picker asks Discord for your channels from the **app** service, so `DISCORD_TOKEN` must be set on the app and not only on the bot. Add it to the app's environment and restart: `docker compose up -d app`.
  </Accordion>
  <Accordion title="The Discord bot will not connect">
    `DISCORD_TOKEN` and `DISCORD_CLIENT_ID` must come from the same Discord application. If you created a new application or regenerated the token, update both together and restart the bot.
  </Accordion>
  <Accordion title="Slack events are not arriving">
    1. Check that `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, and `SLACK_SIGNING_SECRET` are all set.
    2. On the Slack app's Event Subscriptions page, confirm the request URL is publicly reachable and verified.
    3. Look at the logs: `docker compose logs app --tail=50 | grep -i slack`.

    `SLACK_POLL_INTERVAL_SECONDS` only matters in polling mode and defaults to `60`.
  </Accordion>
  <Accordion title="The GitHub webhook returns an error">
    - **503:** `GITHUB_WEBHOOK_SECRET` is not set. Set it to the same value you configured on the GitHub App.
    - **401:** the secret does not match. Check that the value in `.env` has no trailing whitespace or newline, then restart the app and re-deliver the failed webhook from the GitHub App settings page.
  </Accordion>
  <Accordion title="The widget returns an error">
    A 500 from the widget usually means the browser cannot reach the app, or the embed snippet no longer matches the workspace.

    1. Open the browser console and read the error from the failed request.
    2. Confirm the app is reachable at its public address.
    3. In **Settings → Widget**, confirm the widget token in your embed snippet is the current one.
  </Accordion>
</Accordions>

## Still stuck?

Gather the relevant log lines from the app and bot, and the exact error text, before you ask for help. Remove any keys or tokens first.
