answerLoops signs your team in with Google or GitHub. This page walks you through creating OAuth credentials that let answerLoops authenticate users. When you are done, the sign-in page displays buttons for each configured method.

<Callout type="info">
  Discord and Slack connections inside the product are for linking community channels, and the GitHub App integration in Settings connects repositories for documentation sync and issue tracking. Sign-in uses its own Google or GitHub OAuth credentials configured in your environment.
</Callout>

The sign-in page only offers a method whose credentials are set. If neither provider is configured, it shows a notice that sign-in is not set up, instead of a button.

## Create the Google client

<Steps>
  <Step>
    Open [console.cloud.google.com](https://console.cloud.google.com), then go to **APIs & Services** → **Credentials**.
  </Step>
  <Step>
    Select **Create Credentials** → **OAuth client ID**.
  </Step>
  <Step>
    Set the application type to **Web application**.
  </Step>
  <Step>
    Add this authorized redirect URI, using your own address in place of the example:

    - Local: `http://localhost:3000/api/auth/callback/google`
    - Production: `https://<your-domain>/api/auth/callback/google`
  </Step>
  <Step>
    Copy the **Client ID** and **Client secret**, and add them to `.env`:

    ```dotenv
    AUTH_GOOGLE_ID=<your-google-client-id>
    AUTH_GOOGLE_SECRET=<your-google-client-secret>
    ```
  </Step>
</Steps>

Restart the app after changing `.env`. When configured, the sign-in page displays the **Sign in with Google** button.

## Create the GitHub OAuth application

<Steps>
  <Step>
    Go to [github.com/settings/developers](https://github.com/settings/developers), then select **OAuth Apps** → **New OAuth App**.
  </Step>
  <Step>
    Set the **Application name** (for example, `answerLoops`).
  </Step>
  <Step>
    Set the **Homepage URL** to your deployment address:

    - Local: `http://localhost:3000`
    - Production: `https://<your-domain>`
  </Step>
  <Step>
    Add the **Authorization callback URL**:

    - Local: `http://localhost:3000/api/auth/callback/github`
    - Production: `https://<your-domain>/api/auth/callback/github`
  </Step>
  <Step>
    Select **Register application**, then select **Generate a new client secret**.
  </Step>
  <Step>
    Copy the **Client ID** and **Client secret**, and add them to `.env`:

    ```dotenv
    AUTH_GITHUB_ID=<your-github-client-id>
    AUTH_GITHUB_SECRET=<your-github-client-secret>
    ```
  </Step>
</Steps>

Restart the app after changing `.env`. When configured, the sign-in page displays the **Sign in with GitHub** button.

## How sign-in works

<Mermaid
  caption="The sign-in redirect: you start on answerLoops, approve on your provider, and the provider sends you back to your callback address."
  chart={`sequenceDiagram
  participant You
  participant App as answerLoops
  participant Provider as Sign-in Provider
  You->>App: Select sign-in method
  App->>Provider: Redirect to provider to approve
  Provider->>You: Ask you to approve
  You->>Provider: Approve
  Provider->>App: Redirect to /api/auth/callback/<provider>
  App->>You: Signed in, open the dashboard`} />

The callback address in the fifth message is built from `AUTH_URL`, so that variable must match the public address you actually use.

<Callout type="warn">
  The redirect URI in Google or GitHub must match your address exactly. A trailing slash, `http` versus `https`, or a different port each count as a mismatch. If your provider shows a `redirect_uri_mismatch` error, see [troubleshooting](/docs/self-hosting/troubleshooting#sign-in-and-access).
</Callout>
