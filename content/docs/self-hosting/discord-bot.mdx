To connect a self-hosted answerLoops to Discord you need a **bot token** — sometimes called an API key — issued by Discord's Developer Portal. This page covers the direct route: create a Discord application, copy its token, and paste it into answerLoops Settings for a single server. If you're on the managed cloud platform instead, or want one-click OAuth so anyone in your org can connect their own server without touching a token, see the [Discord integration guide](/docs/integrations/discord).

## Self-hosted setup

### 1. Create a Discord Application and copy the bot token

1. Go to [discord.com/developers/applications](https://discord.com/developers/applications)
2. Click **New Application** → name it (e.g. "answerLoops")
3. Go to **Bot** tab → **Add Bot**
4. Under **Token** → **Reset Token** → copy it — this is your bot token (API key)

```dotenv
DISCORD_TOKEN=your_bot_token
DISCORD_APPLICATION_ID=your_application_id  # from General Information tab
```

### 2. Set bot permissions

Under **Bot** tab, enable these **Privileged Gateway Intents**:
- Message Content Intent
- Server Members Intent (optional, for role pings)

### 3. Invite the bot to your server

Go to **OAuth2 → URL Generator**:
- Scopes: `bot`, `applications.commands`
- Bot permissions: `Send Messages`, `Read Message History`, `View Channels`, `Use Slash Commands`

Copy the generated URL and open it in your browser to invite the bot.

### 4. Get channel IDs

Enable Developer Mode: Discord → User Settings → Advanced → Developer Mode ✓

Right-click a channel → **Copy Channel ID**

### 5. Configure in answerLoops Settings

Go to **Integrations → Discord** and enter:
- **Bot Token** — same as `DISCORD_TOKEN`
- **Channel IDs** — channels to listen on (comma-separated)
- **Escalation Role ID** (optional) — role to @mention when AI confidence is low
- **Confidence threshold** — 0–1, default 0.8

## Config hot-reload

The bot uses Postgres `LISTEN/NOTIFY` to pick up config changes instantly — no restart needed.

When you save changes in **Integrations → Discord** (channel IDs, bot token, confidence threshold), the database fires a `pg_notify('config_changed')` event. The bot's dedicated listener connection receives it and reloads config within milliseconds.

The bot also updates its channel→guild map automatically whenever it joins or leaves a server (`GuildCreate` / `GuildDelete` events) — no manual ID entry required.

Both `integrations` (bot token, single-org channel config) and `discord_guilds` (per-guild channel picks for OAuth-connected servers) carry this trigger — a write to either one notifies the bot.

<Note>
The bot maintains one dedicated Postgres connection for `LISTEN`. This is separate from the connection pool and is closed cleanly on `SIGTERM`/`SIGINT`.
</Note>

That connection sends itself a heartbeat query every 4 minutes. On a serverless Postgres provider an idle compute can auto-suspend, silently killing every connection on it — LISTEN included — with no clean disconnect for the bot to react to; a long-idle TCP connection can also get dropped by an intermediate network proxy the same way. The heartbeat keeps the compute active and detects a dead connection quickly. If a heartbeat fails, the LISTEN connection closes, or the initial `LISTEN` fails, the bot reconnects and re-subscribes automatically after a short delay — no manual restart needed to recover config hot-reload.

## Slash commands

Once connected, answerLoops registers these slash commands:
- `/ask [question]` — search the knowledge base and return the best match
- `/summarize` — summarize the current thread as bullet points

Slash commands require `DISCORD_APPLICATION_ID` to be set — see the [full registration steps](/docs/integrations/discord#slash-commands) in the Discord integration guide.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Invalid token / bot won't log in">
    Bot tokens are only shown once when generated. If you didn't copy it at creation, go back to the **Bot** tab and click **Reset Token** to generate a new one — the old one stops working immediately. Make sure `DISCORD_TOKEN` has no surrounding quotes or whitespace in your `.env` file.
  </Accordion>
  <Accordion title="401 Unauthorized on connect">
    The token in `DISCORD_TOKEN` doesn't match a live application, or was reset in the Developer Portal after you copied it. Reset the token again, update `DISCORD_TOKEN`, and restart the bot service.
  </Accordion>
  <Accordion title="Bot connects but never sees messages">
    **Message Content Intent** must be enabled under the **Bot** tab's Privileged Gateway Intents — without it, Discord's gateway strips message content before the bot ever receives it, so nothing gets ingested even though the bot appears online.
  </Accordion>
  <Accordion title="Bot doesn't appear in the channel picker or can't be invited">
    Confirm the OAuth2 URL Generator step used both the `bot` and `applications.commands` scopes, and that you opened the generated URL (not just copied it) to complete the invite. A bot that was never invited to the server won't show up anywhere in answerLoops.
  </Accordion>
</AccordionGroup>
