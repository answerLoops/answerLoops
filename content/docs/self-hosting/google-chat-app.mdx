description: One-time Google Cloud configuration that lets a self-hosted answerLoops deployment receive and reply to Google Chat messages.

---

Google Chat has no "install" button that answerLoops can drive for an arbitrary Workspace, so a self-hosted deployment needs its own Chat app. You create it once in Google Cloud, and every organization on your deployment then pairs a space to it with a connect code. This page is the one-time operator setup.

When you are done, your deployment has a Chat app listening at your public address, and your team can connect spaces from **Integrations → Google Chat**. What they do from there (generating a connect code, posting `/connect`, escalation and thresholds) is in the [Google Chat integration guide](/docs/integrations/google-chat).

<Callout type="info">
  **You do this once for the whole deployment, not once per organization.** All organizations share the one Chat app you create here.
</Callout>

## Set up the Chat app

<Steps>
  <Step title="Create or choose a Google Cloud project">
    Open the [Google Cloud Console](https://console.cloud.google.com) and create a project, or reuse one you already have.
  </Step>
  <Step title="Enable the Google Chat API">
    Go to **APIs & Services → Library**, search for **Google Chat API** and click **Enable**.
  </Step>
  <Step title="Create a service account and a JSON key">
    Go to **IAM & Admin → Service Accounts → Create Service Account**. No special IAM roles are needed for basic messaging, because the Chat API authorizes through the Chat app configuration rather than project roles. Create a JSON key for the account and keep it somewhere safe. It becomes `GOOGLE_CHAT_SERVICE_ACCOUNT_JSON`.
  </Step>
  <Step title="Configure the Chat app">
    In **Google Chat API → Configuration**, set:

    - **App name, avatar and description** to whatever you want people to see.
    - **Functionality** to "Receive 1:1 messages" and "Join spaces and group conversations".
    - **Connection settings → HTTP endpoint URL** to your public endpoint:

      ```text
      https://<your-domain>/api/google-chat/events
      ```

    - **Visibility**. For an unlisted app used outside your own Workspace, list the domains, users or groups allowed to install it.
  </Step>
  <Step title="Set the environment variables">
    Set both variables on the `app` service and restart it:

    ```dotenv
    GOOGLE_CHAT_SERVICE_ACCOUNT_JSON=<the full JSON key as a single-line string>
    GOOGLE_CHAT_ENDPOINT_URL=https://<your-domain>/api/google-chat/events
    ```
  </Step>
  <Step title="Connect an organization">
    Any owner or admin can now open **Integrations → Google Chat** and follow the [connect-code flow](/docs/integrations/google-chat#the-connect-code-pairing-flow).
  </Step>
</Steps>

<Callout type="warn">
  `GOOGLE_CHAT_ENDPOINT_URL` must exactly match the HTTP endpoint URL you entered in the Chat app configuration, including any trailing slash. If they differ, Google Chat events are rejected and nothing reaches answerLoops.
</Callout>

## Who can install the app

The Chat app you just created is an **unlisted app**. It is quick to stand up, but each customer's Workspace admin has two manual steps: enabling third-party Chat apps for their domain (in their **Admin Console → Apps → Google Workspace Marketplace apps** settings), then adding the app to a space.

A [Google Workspace Marketplace](https://developers.google.com/workspace/marketplace/about-app-review) listing lets a customer install in a couple of clicks with no admin-console detour, at the cost of a one-time Google review (OAuth verification and listing review, commonly a few weeks). Both routes use the same endpoint and environment variables, so listing later does not mean redoing this setup. The Marketplace submission asks for a public privacy policy URL, and the hosted deployment already serves one at `/privacy`.

## Troubleshooting

<Accordions>
  <Accordion title="Messages in the space never reach answerLoops">
    Check that the HTTP endpoint URL in the Chat app configuration, `GOOGLE_CHAT_ENDPOINT_URL` and your real public address are all identical, and that the `app` service was restarted after you set the variables.
  </Accordion>
  <Accordion title="The app cannot be added to a space">
    The Workspace admin on the installing side may need to enable third-party Chat apps for their domain first, and the person adding the app must be inside the **Visibility** list you configured.
  </Accordion>
</Accordions>
