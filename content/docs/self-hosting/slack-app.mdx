Slack connects the same way on a self-hosted deployment as on managed cloud — there's no separate self-hosting setup path. Create a Slack app at [api.slack.com/apps](https://api.slack.com/apps), grant it the required bot token scopes, and either connect via 1-click OAuth or paste the bot token in manually if you can't get admin approval for an OAuth install. See the [full Slack setup guide](/docs/integrations/slack) for both paths, the feature comparison table, and troubleshooting.

## Self-hosting-specific env vars

Self-hosted deployments configure OAuth and polling through environment variables that managed cloud already has set:

```dotenv
SLACK_CLIENT_ID=your_app_id.your_workspace_id       # enables the Add to Slack 1-click flow
SLACK_CLIENT_SECRET=your_client_secret
SLACK_SIGNING_SECRET=your_signing_secret            # only needed for the Events API webhook
AUTH_URL=https://your-domain.com                    # Slack redirects to {AUTH_URL}/api/slack/callback
SLACK_POLL_INTERVAL_SECONDS=60                       # optional, self-hosted polling mode only
```

For OAuth scopes, the manual-polling path for deployments that can't get admin approval or expose a public webhook, and the full environment variable reference, see [Slack](/docs/integrations/slack).
