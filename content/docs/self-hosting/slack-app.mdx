Connecting a workspace to Slack works the same on a self-hosted deployment as on the managed cloud, with one difference: on managed cloud the Slack app already exists, and on your deployment **you** create it. This page is the short operator checklist for that. When you are done, your team can click **Add to Slack** (or paste a token) in **Integrations → Slack**.

Everything your team does after that (channel picking, private channels, escalation, Automatic Deflections, troubleshooting) is in the [Slack integration guide](/docs/integrations/slack). This page only covers what the operator sets up.

## Pick how messages reach answerLoops

| | Events API | Polling |
| --- | --- | --- |
| How it works | Slack sends each message to your app as it is posted | The bot service asks Slack for new messages on an interval (every 60 seconds by default) |
| Needs a public URL for Slack to call | Yes | No |
| Needs the Slack signing secret | Yes | Optional |
| Delay | Instant | Up to the poll interval |

Polling runs inside the `bot` service for every active Slack workspace on a self-hosted deployment, so the bot must be running. The two can be used together, but most operators choose one.

## Operator checklist

<Steps>
  <Step title="Create the Slack app">
    Go to [api.slack.com/apps](https://api.slack.com/apps) and create an app for your workspace. If you only plan to paste a token by hand (polling), you can skip the next two steps and generate the bot token from the app's **OAuth & Permissions** page.
  </Step>
  <Step title="Add the redirect URL and scopes">
    Under **OAuth & Permissions → Redirect URLs**, add:

    ```text
    <your-app-url>/api/slack/callback
    ```

    `<your-app-url>` is your public address, the value of `AUTH_URL`. Add these bot token scopes: `channels:history`, `channels:read`, `channels:join`, `chat:write`, `reactions:write` and `users:read`. They are the same scopes the **Add to Slack** button requests.
  </Step>
  <Step title="Set the environment variables">
    Set the variables from the table below on the `app` service (and `SLACK_POLL_INTERVAL_SECONDS` on the `bot` service), then restart them.
  </Step>
  <Step title="For real-time events, subscribe to them">
    In the Slack app's **Event Subscriptions**, switch events on and set the Request URL to `<your-app-url>/api/slack/events`. Subscribe to the bot events `message.channels` and `reaction_added`. Skip this step if you are using polling.
  </Step>
  <Step title="Connect from the product">
    Open **Integrations → Slack**. Click **Add to Slack** for the one-click install, or **Set up manually instead** (shown only on self-hosted deployments) to paste a bot token, the workspace Team ID and channel IDs. The [integration guide](/docs/integrations/slack#option-1-1-click-oauth-recommended) takes it from there.
  </Step>
</Steps>

## Environment variables

| Variable | Set on | What it does |
| --- | --- | --- |
| `SLACK_CLIENT_ID` | `app` | The Slack app's Client ID. Turns on the **Add to Slack** button |
| `SLACK_CLIENT_SECRET` | `app` | The Client Secret, used with the Client ID |
| `SLACK_SIGNING_SECRET` | `app` | The Slack app's Signing Secret, from **Basic Information**. Needed for the Events API, optional for polling |
| `AUTH_URL` | `app` | Your public app URL. Slack returns people to `<your-app-url>/api/slack/callback` |
| `SLACK_POLL_INTERVAL_SECONDS` | `bot` | Optional polling interval. Default `60`, minimum recommended `30`. Restart the `bot` service after changing it |
| `BOT_TARGET_URL` | `bot` | Address the polling bot uses to reach the app, with no trailing slash. The bundled `docker-compose.yml` already sets it |

The full list is in [Environment Variables](/docs/self-hosting/environment-variables).

<Callout type="info">
  The first poll of a channel never imports history. It only marks where the channel is now, so connecting an active channel does not flood your tickets with old messages.
</Callout>
