answerLoops uses a language model to draft answers and an embedding model to
search your knowledge base. **Settings → AI Model** controls which provider and
models an org uses.

## What runs by default

| State | What's used |
|---|---|
| A hosted workspace, no key configured | **Included AI usage**, up to a limit — for the whole trial, then monthly on a paid plan |
| AI limit reached, still no key | That part of AI pauses until you connect a provider (or, on a paid plan, until next month) |
| Own chat key from a provider other than OpenAI, no embedding key | Answers on your key; knowledge‑base processing on included usage until you add an OpenAI embedding key |
| Self‑hosted | The `OPENAI_API_KEY` in your environment |
| A workspace with saved model settings | Its configured chat and embedding services |

On included usage, answerLoops chooses the models, and the card lists them
read‑only. To pick your own models, add your own provider. The card shows
where you stand — included usage, "limit reached", or the
configured provider and model. See [Billing](/docs/product/billing) for how
the limits work.

## Bring your own provider

Included on every plan for the named providers below. A custom
OpenAI‑compatible endpoint (your own base URL — Ollama, LM Studio, vLLM, a
proxy) is part of **Custom AI model configuration**, which is included on Enterprise and in the self-hosted edition. On the hosted service a custom base URL must be an https address reachable on the public internet. Self-hosted installs can also use `http` and addresses on their own network, such as a local Ollama server. Link-local and cloud-metadata addresses are never allowed. Every chat and embedding request connects to the address that was checked when the call started.

| Provider | Chat | Embeddings |
|---|---|---|
| OpenAI | ✓ | ✓ (same key covers both) |
| Anthropic | ✓ | — (no embeddings API) |
| Google Gemini | ✓ | Coming soon |
| Groq | ✓ | — (no embeddings API) |
| Mistral | ✓ | Coming soon |
| xAI (Grok) | ✓ | — (no embeddings API) |
| OpenAI‑compatible endpoint | ✓ (Enterprise) | ✓ (Enterprise) |

**OpenAI is the only provider that can handle knowledge‑base processing
(embeddings) today.** Google Gemini and Mistral are coming soon. Every other
provider in the table covers answers only.

If your chat provider isn't OpenAI:

- **On a hosted plan**, the OpenAI key under **Embeddings** is optional. Leave
  it blank and knowledge‑base processing runs on your plan's included AI usage.
  Add an OpenAI key to remove that limit.
- **On a self‑hosted install**, enter an **OpenAI API key under Embeddings** (or
  use a custom embedding endpoint). Otherwise knowledge‑base search and every
  ingest would fail, so the save is rejected with a clear message if it's
  missing.

### Steps

1. **Settings → AI Model → Edit** (or **Save** for a first‑time setup — owner or
   admin only).
2. Pick the **chat provider**, enter its **API key**, then click **Refresh
   models** to pull that provider's current model list live — Model ID stays a
   dropdown of whatever that provider actually offers today instead of a list
   that goes stale between releases. If the live fetch fails (or before you've
   run it), Model ID falls back to a built‑in list of recent models, or you can
   type an ID directly with **Custom model ID…**.
3. Pick the **embedding provider** and model. If the chat provider isn't
   OpenAI, add an OpenAI embedding key (optional on a hosted plan, where
   leaving it blank uses included AI usage).
4. Click **Test connection** — this makes a one‑token call to each provider with
   the values you entered (nothing is saved yet) and reports `chat: connection
   OK` / `embedding: …` or a specific error (rejected key, unknown model,
   unreachable endpoint). With no embedding key on a hosted plan, the embedding
   line says knowledge‑base processing will use included AI usage instead.
5. Click **Save**.

### Changing provider later

If you switch the chat or embedding provider and leave the key field blank, the
save is rejected — the stored key belonged to the previous provider and would
fail on every call. Enter a key for the new provider. (A keyless local endpoint
is the exception: switching to `openai-compatible` with no key clears the old
one.)

Leaving a key field blank on an update to the **same** provider keeps the
stored key — the field shows "Key saved".

## Reset

**Reset to platform default** deletes the org's AI config. A hosted workspace
falls back to included usage (or, once the limit is reached, to no AI until next
month); a self‑hosted deployment falls back to its environment key.

If your embedding model changes (you switch it here, or answerLoops changes
the included one), your knowledge base is re‑embedded in the background from
what you already added. Search keeps working throughout, and you don't need to
re‑upload anything.
