This release adds per-article usage counts to Knowledge coverage, starts recording who added each knowledge-base article and how it changed over time, and makes every dashboard stat card link to the tickets behind its number.

### ⚠️ Upgrade steps
- Two database migrations run automatically on start: `0059_kb_article_created_by` and `0060_kb_article_events`. Both are additive and safe to re-run. Existing articles are not backfilled, so an empty "added by" means unknown. ([#434](https://github.com/answerLoops/answerLoops/issues/434), [#436](https://github.com/answerLoops/answerLoops/issues/436))

### New
- **Article usage on Knowledge coverage** — each article shows how many times it was supplied to the assistant as context, over the retained window (up to 400 days) and the last 30 days. If usage can't be loaded, the page says "Usage unavailable" instead of showing zero. [Docs](https://answerloops.com/docs/product/knowledge-base) ([#441](https://github.com/answerLoops/answerLoops/issues/441), [#459](https://github.com/answerLoops/answerLoops/issues/459))
- **Clickable dashboard stat cards** — Auto-Answered, Needs Review, AI Drafts Pending and SLA Breaches open the tickets page with a matching filter, and Deflection Rate opens Analytics. The tickets page shows a "Filtered by" label and keeps the filter when you press Filter or Load more. [Docs](https://answerloops.com/docs/product/tickets) ([#421](https://github.com/answerLoops/answerLoops/issues/421), [#460](https://github.com/answerLoops/answerLoops/issues/460))
- **Who added each article** — articles written by hand, promoted from a ticket, or approved from the review queue now record the team member who added them. Imports and syncs leave it empty. ([#434](https://github.com/answerLoops/answerLoops/issues/434))
- **Article history** — every create, promote, approve, reject, reopen, import, sync and edit is recorded in an append-only history. It stores a fingerprint of the text, not the text itself. Nothing displays it yet. ([#435](https://github.com/answerLoops/answerLoops/issues/435), [#436](https://github.com/answerLoops/answerLoops/issues/436))
- **Blog** — new post on turning support answers into a searchable knowledge base, with its own cover art. ([#449](https://github.com/answerLoops/answerLoops/issues/449), [#451](https://github.com/answerLoops/answerLoops/issues/451), [#454](https://github.com/answerLoops/answerLoops/issues/454))

### Improved
- The Deflection Rate card now shows the same figure as Analytics (bug reports and feature requests are left out). ([#421](https://github.com/answerLoops/answerLoops/issues/421))
- Header and footer Docs links go through a tracked link on hosted builds; self-hosted and local builds keep the in-app `/docs` route. ([#416](https://github.com/answerLoops/answerLoops/issues/416))
- Bug, feature, integration and docs issue forms are now available on GitHub. ([#418](https://github.com/answerLoops/answerLoops/issues/418))

### Fixed
- Markdown images in blog posts rendered as broken images. They now display correctly. ([#451](https://github.com/answerLoops/answerLoops/issues/451))
- A pruning off-by-one kept 401 days of article usage instead of 400. It now keeps exactly 400. ([#459](https://github.com/answerLoops/answerLoops/issues/459))
- `CLOUDFLARE_WEB_ANALYTICS` set on the host never reached the Docker build, so the analytics beacon was blocked by the content security policy. ([#411](https://github.com/answerLoops/answerLoops/issues/411))

### Configuration changes
| Variable | Required | Purpose |
|---|---|---|
| `CLOUDFLARE_WEB_ANALYTICS` | no | Now declared as a Docker build argument, so setting it on the host takes effect when you build the image. |

### Security
This release includes security fixes.
