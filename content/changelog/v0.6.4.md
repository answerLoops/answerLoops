Hosted workspaces now get AI usage included, so a new workspace can use answerLoops before connecting its own provider. The knowledge base gains a review queue, an add-knowledge form and a coverage view. Connecting a channel now tells you exactly what happened and what is left to do.


### What's New
- **Included AI usage on hosted plans** — hosted workspaces run on the platform's models within a usage allowance, with separate budgets for answers and for knowledge-base processing, through the trial and then each month. Connecting your own provider removes the limit, and any supported chat provider works without a separate embedding key. A dashboard banner warns at 80% and when usage runs out. [Docs](https://answerloops.com/docs/product/ai-config) ([#373](https://github.com/answerLoops/answerLoops/issues/373), [#381](https://github.com/answerLoops/answerLoops/issues/381))
- **Knowledge review queue** — questions the assistant couldn't answer land in a per-workspace queue on the Knowledge Base page, most-asked first. Owners and admins edit and approve them into published articles, or reject them. [Docs](https://answerloops.com/docs/product/knowledge-base) ([#362](https://github.com/answerLoops/answerLoops/issues/362))
- **Add knowledge from the dashboard** — a form on the Knowledge Base page writes a question and answer straight into the KB. [Docs](https://answerloops.com/docs/product/knowledge-base) ([#367](https://github.com/answerLoops/answerLoops/issues/367))
- **Knowledge coverage tab** — shows what the chat assistant can answer from: article counts by state, grouped by source. [Docs](https://answerloops.com/docs/product/chat-widget) ([#337](https://github.com/answerLoops/answerLoops/issues/337))
- **Rich answer cards in the chat widget** — step-by-step guides, quick replies, callouts, link cards and contact options, plus a faster first response. [Docs](https://answerloops.com/docs/product/chat-widget) ([#329](https://github.com/answerLoops/answerLoops/issues/329))
- **Channels first** — after connecting a Discord server, the card says "This server does not have any channels connected", shows a "Needs channels" status, and opens the channel picker straight away. Failed connects now show the reason on screen until dismissed. [Docs](https://answerloops.com/docs/integrations/discord) ([#384](https://github.com/answerLoops/answerLoops/issues/384), [#385](https://github.com/answerLoops/answerLoops/issues/385))
- **Sign-in page redesign** — a new two-panel layout. A sign-in method's button appears only when its credentials are set; an install with none sees an explanation and a link to the self-hosting guide. [Docs](https://answerloops.com/docs/self-hosting/oauth) ([#371](https://github.com/answerLoops/answerLoops/issues/371))

### Improved
- **Simulation and file uploads** stop cleanly when included AI usage runs out part-way, keep what they finished, and say why. ([#378](https://github.com/answerLoops/answerLoops/issues/378))
- **Old manual Discord setups** now read "Not receiving" on the hosted product instead of "Connected" and "Active", with a one-click way to switch. ([#385](https://github.com/answerLoops/answerLoops/issues/385))
- **Widget branding removal** is a Pro-and-above feature on hosted plans. Self-hosted installs have every feature unlocked. ([#340](https://github.com/answerLoops/answerLoops/issues/340))
- **Dev stack** — the development compose file now points live updates at the local Postgres container, and the docs describe the database as managed Postgres with pgvector. ([#338](https://github.com/answerLoops/answerLoops/issues/338))

### Fixed
- Connecting Discord, Slack, Gmail or Outlook gave no confirmation or error, and the Discord channel picker never opened. The result is shown again. ([#384](https://github.com/answerLoops/answerLoops/issues/384))
- The knowledge-base re-embedding sweep could not reach its route, so it never ran. ([#376](https://github.com/answerLoops/answerLoops/issues/376))
- Dashboard cards and links went to the wrong place: "view all" tickets, the progress and resolved cards, and the Website link. An unverified sidebar status badge was removed. ([#304](https://github.com/answerLoops/answerLoops/issues/304), [#305](https://github.com/answerLoops/answerLoops/issues/305), [#307](https://github.com/answerLoops/answerLoops/issues/307))
- Feature requests no longer count against deflection metrics. ([#308](https://github.com/answerLoops/answerLoops/issues/308))
- The chat widget embed snippet and site headers, alt text and contrast were tidied after a public website audit. ([#355](https://github.com/answerLoops/answerLoops/issues/355))
- Hosted checkout: more reliable when a stored customer no longer exists, with clearer errors and retries on gateway failures. ([#356](https://github.com/answerLoops/answerLoops/issues/356), [#357](https://github.com/answerLoops/answerLoops/issues/357), [#358](https://github.com/answerLoops/answerLoops/issues/358), [#359](https://github.com/answerLoops/answerLoops/issues/359))

### Agent SDK
No changes in this release.

### Configuration changes
| Variable | Required | Purpose |
|---|---|---|
| `DISCORD_TOKEN` | yes, for one-click Discord | Must also be set on the app service, not only the bot. |
| `GITHUB_APP_CLIENT_ID` | yes, for the GitHub App | The GitHub App's Client ID. |
| `GITHUB_APP_CLIENT_SECRET` | yes, for the GitHub App | A client secret generated in the GitHub App settings. |
| `TELEGRAM_WEBHOOK_BASE_URL` | no | Overrides `AUTH_URL` for the Telegram webhook only. |
| `TELEGRAM_BOT_TOKEN` | removed | Save the token per workspace in Integrations → Telegram. |
| `PLATFORM_AI_CHAT_MODEL`, `PLATFORM_AI_FAST_MODEL`, `PLATFORM_AI_EMBEDDING_MODEL` | no | Models used for included usage on hosted deployments. |
| `PLATFORM_AI_TRIAL_*_BUDGET_USD`, `PLATFORM_AI_PLAN_*_BUDGET_USD` | no | Included-usage budgets for the trial and for paid plans, for chat and embeddings. |

See the [environment variable reference](https://answerloops.com/docs/self-hosting/environment-variables) for defaults and the full list.
