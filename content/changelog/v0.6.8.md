A card-free 14-day trial on the hosted product, a chat widget that answers first and asks for an email only after it fails to help, a stable public widget name that survives token rotation, and a lot more visibility into GitHub-sourced tickets and saved resolutions in the knowledge base.

### ⚠️ Breaking changes & upgrade steps
- No breaking changes. Ten new database migrations (`0067` to `0076`) run automatically when the app starts, so there is nothing to run by hand. Self-hosters: pull the new image and restart.
- The chat widget's email behavior is now a per-workspace setting. New workspaces default to asking only after a turn the widget couldn't answer; every workspace that already existed keeps the old up-front email gate until its owner changes it in **Settings → Widget → Ask for an email**. ([#545](https://github.com/answerLoops/answerLoops/issues/545))

### New
- **Ask for an email only after a miss** — the widget now answers a visitor's first message right away. Pick `on-failure`, `up-front` or `off` per workspace; the lead is attached to the question the widget couldn't answer. [Docs](https://answerloops.com/docs/product/chat-widget) ([#545](https://github.com/answerLoops/answerLoops/issues/545))
- **Stable public widget name** — owners can set an optional name such as `acme-support` in Settings. The install snippet then carries that name instead of the token, so rotating the token no longer breaks live embeds. Snippets that carry a token keep working. [Docs](https://answerloops.com/docs/product/chat-widget) ([#560](https://github.com/answerLoops/answerLoops/issues/560))
- **Widget display settings from the server** — the embed script now fetches its window size and bubble color from `GET /api/widget/config?id=<token>` and falls back to the default look if the lookup is slow or fails, so existing installs need no re-paste. ([#558](https://github.com/answerLoops/answerLoops/issues/558))
- **Card-free 14-day trial (hosted)** — new accounts get one trial of every feature with no card. A single sign-in page and a short terms step replace the old flow, with a welcome email, a last-three-days banner and reminder emails. Self-hosted deployments are not affected. [Docs](https://answerloops.com/docs/product/billing) ([#532](https://github.com/answerLoops/answerLoops/issues/532))
- **Customer replies are noticeable on any ticket** — replies show in the bell (with **Mark all read**), an **Activity** panel on the dashboard, a **New activity** filter on the ticket list, and browser push notifications, and go quiet once the team opens the ticket. [Docs](https://answerloops.com/docs/product/tickets) ([#538](https://github.com/answerLoops/answerLoops/issues/538))
- **GitHub issue and discussion references on tickets** — a ticket header now reads `Issue owner/repo#123` or `Discussion owner/repo#45`, and the Tickets list shows the same reference. ([#537](https://github.com/answerLoops/answerLoops/issues/537))
- **Comments on closed GitHub issues join the ticket** — a comment on a closed issue now joins that issue's ticket and reopens it if it was resolved. A one-off `pnpm github:backfill-threads --org=<id>` command (with `--dry-run`) folds older comment tickets into their threads. [Docs](https://answerloops.com/docs/integrations/github) ([#536](https://github.com/answerLoops/answerLoops/issues/536))
- **Which commit a repo sync reflects** — the Knowledge Base page and the GitHub settings row show the commit the last sync read, as a short link. [Docs](https://answerloops.com/docs/integrations/github) ([#561](https://github.com/answerLoops/answerLoops/issues/561))
- **Saved resolutions show when they were saved** — the Manage tab shows when each one was last saved, with a sort (newest or oldest saved first) and a "Saved resolutions only" filter. [Docs](https://answerloops.com/docs/product/knowledge-base) ([#562](https://github.com/answerLoops/answerLoops/issues/562))
- **Resolutions flagged when related docs change** — when a repo sync changes docs close in meaning to a saved resolution, that resolution is flagged for review. [Docs](https://answerloops.com/docs/product/knowledge-base) ([#566](https://github.com/answerLoops/answerLoops/issues/566))
- **Up-votes on the product feedback board (hosted)** — approved entries carry an up arrow and count, and **Most voted** ranks the whole board. [Docs](https://answerloops.com/docs/product/feedback-board) ([#552](https://github.com/answerLoops/answerLoops/issues/552), [#567](https://github.com/answerLoops/answerLoops/issues/567))

### Improved
- The homepage now leads with the answer-loop overview diagram, and the self-hosting quickstart opens with an install-flow diagram. ([#551](https://github.com/answerLoops/answerLoops/issues/551), [#527](https://github.com/answerLoops/answerLoops/issues/527))
- The docs sidebar's **Log in** and **Start trial** buttons are restyled, and the OpenAI integration shows its official logo. ([#549](https://github.com/answerLoops/answerLoops/issues/549), [#533](https://github.com/answerLoops/answerLoops/issues/533))
- Deploy settings for the hosted app and bot moved into code-based platform config. This changes nothing for Docker or self-hosted installs. ([#542](https://github.com/answerLoops/answerLoops/issues/542), [#547](https://github.com/answerLoops/answerLoops/issues/547), [#548](https://github.com/answerLoops/answerLoops/issues/548))

### Fixed
- Welcome emails that the email provider rejected used to fail silently; the rejection is now logged, and a missing API key logs a warning. ([#550](https://github.com/answerLoops/answerLoops/issues/550))
- Feedback board (hosted): when a **Most voted** request failed, the button looked selected while the list stayed in the old order. The highlight now always matches the order on screen. ([#567](https://github.com/answerLoops/answerLoops/issues/567))

### Agent SDK and widget packages
- No code changes. `@answerloops/agent-sdk` and `@answerloops/widget` are republished as `0.6.8` so all three versions stay aligned.

Security fixes are included in this release.
